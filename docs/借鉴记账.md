> 说明：三个函数**全部自写实现**（numpy 向量化，无 Python 逐像素循环），未复制 FastNoiseLite 的 C#/C++ 源码。

### 实现口径（会影响结果，写清楚免得后人误判"算错了"）

- `cellular_noise` 的 f1 / f2 / f2f1 **共用除数 √2**（3×3 搜索下的 F1 理论上界）。好处是三种类型可直接比较、可叠加；代价是 f1 实测很少超过 ~0.72。若将来更在意对比度，可改成按类型分别归一（会破坏三者可比性），届时须同步改测试。
- 3×3 邻域在 `jitter=1` 时是**近似** Voronoi（严格解需要搜索偏移 2 的格点，概率极低）。已写进 docstring。
- `warp_noise(warp_strength=0)` 逐位等于基噪声直采 —— 这是测试钉住的不变量。

## 五、待复核

1. 黄金值测试绑定了 **numpy 版本**（`np.cos/sin` 的最低位可能随 SIMD 实现变化）。换环境后请用 `git show HEAD:worldbuilder/noise.py` 重算黄金值，**不要**放宽成容差比较。
2. `fbm` 等旧函数在**标量输入**时会触发 `RuntimeWarning: overflow encountered in scalar multiply`（`_hash2` 的 int64 溢出，阵列输入无此问题）——属既存问题，本轮为守住"旧函数零改动"红线未修。
3. **纬度默认铺满 `+90°…-90°`**（整幅图当一张全球图）。做区域图时不传 `latitude=` 会同时出现极地和赤道 —— 这是有意为之的默认，但容易被误用。
4. **降水是相对指数**（按 `reference=0.08` 归一），不是毫米年降水量。跨世界横向比较前先统一 `reference`。
5. **填洼是 Python 堆实现的 O(n log n)**，单次上限 400 万格（`max_cells`）。2048²=419 万格刚好超线，需要时先分块。
6. **小湖偏多**：fBm 地形里大量 4~10 格的小水塘都会被 `lakes()` 记成湖（160² 约 110 个）。要"大湖才算湖"就调 `min_area`。
7. 高纬度的温度带与"苔原占比 ~20%"是**全球图**的合理值；若下游只想要温带区域，请直接给 `latitude=`。
